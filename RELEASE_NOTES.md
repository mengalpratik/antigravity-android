## Новые возможности и изменения (v2.5.0) / Highlights & Changes

### 1. Архитектура централизованного рабочего пространства (Centralized Workspace Architecture)
* **Структура директорий `Antigravity/` по умолчанию:**
  * `Workspace/<ProjectName>/`: выделенная директория для планирования, архитектурных спецификаций, исследований, аудитов и сессий ИИ-агента;
  * `Projects/<ProjectName>/`: изолированное хранилище фактического исходного кода проектов;
  * `Templates/`: встроенные шаблоны проектов, документации и системной архитектуры (`project-templates/`, `documentation-templates/`, `architecture-templates/`);
  * `Exports/`: централизованный экспорт отчетов, пакетов документации и резервных копий (`reports/`, `documentation-packages/`, `backups/`);
  * `Shared/`: общие руководства, ссылки и ресурсы разработчика (`references/`, `resources/`, `common-guidelines/`).
* **Четкое разделение (Separation of Concerns):** Исходный код проекта не засоряется избыточной документацией; вся история проектирования и протоколы взаимодействия хранятся централизованно в `Workspace/`.

### 2. Единый реестр проектов (Unified SQLite Project Registry)
* **Потокобезопасная база данных `antigravity_projects.db` (`ProjectRegistryRepository.java`):**
  * Хранение уникальных UUID проектов, путей к исходному коду, путей к рабочей документации, статусов (`ACTIVE`/`ARCHIVED`), типов размещения (`DEFAULT`/`CUSTOM`) и версий схемы (`1.0.0`).
* **Манифест `project.yaml` (`ProjectYamlParser.java`):**
  * Человекочитаемый манифест метаданных без внешних зависимостей в корне каждого проекта.

### 3. Рабочие процессы проектов (Project Workflows)
* **Quick Project (Быстрый проект):** Создание структуры проекта в `Antigravity/Projects/` и документации в `Antigravity/Workspace/` в 1 действие.
* **Import Existing Project (Импорт существующего проекта):** Подключение любого внешнего каталога с сохранением исходного расположения и автоматической инициализацией централизованной документации.
* **Reconnect Project (Переподключение):** Обнаружение перемещенных или временно недоступных каталогов с сохранением Project ID и истории.

### 4. REST API шлюза System Gateway (`WorkspaceGatewayHandler.java`)
* Маршруты на `127.0.0.1:45160`:
  * `GET /workspace/list`
  * `POST /workspace/quick-create`
  * `POST /workspace/import`
  * `POST /workspace/reconnect`
  * `POST /workspace/archive`
  * `POST /workspace/restore`
  * `POST /workspace/remove`
  * `POST /workspace/verify`

### 5. Автоматическая миграция проектов (Legacy Migration)
* Модуль `OnboardingSeeder.java` автоматически сканирует `/storage/emulated/0/Projects/` и регистрирует существующие проекты в новой централизованной структуре без потери данных.

## Изменения и исправления (v2.4.2)

### 1. Нативная интеграция Superuser Root (`su`) и фоновые привилегии
* **Автоматическое обнаружение провайдеров Root:** Интегрирован модуль `RootBridge.java` с поддержкой KernelSU, Magisk, APatch и стандартного `su` (`/system/bin/su`, `/system/xbin/su`, `/data/adb/ksu/bin/su`).
* **Бесшовный авто-грант разрешений (Zero-Prompt Setup):** При наличии активного Root приложение в фоне автоматически предоставляет все права (`MANAGE_EXTERNAL_STORAGE`, `READ/WRITE_EXTERNAL_STORAGE`, `SYSTEM_ALERT_WINDOW`, `POST_NOTIFICATIONS`) и вносит пакет в белый список энергосбережения (`deviceidle whitelist`), исключая всплывающие диалоги системы.
* **Поддержка Root в шлюзе исполнения (`ExecHandler`):** Добавлены параметры `root: true` и `auto_elevate: true` для привилегированного выполнения команд от имени `uid=0`.

### 2. Режим Turbo и политики выполнения команд по умолчанию
* **Предустановка Turbo Mode:** В конфигурацию по умолчанию `~/.gemini/config/config.json` (`OnboardingSeeder.java`) интегрированы параметры:
  * `permissionPreset: 3` (Turbo Mode);
  * `autoExecutionPolicy: 3` (EAGER / «Always Proceed» — прямое выполнение команд терминала без необходимости подтверждения);
  * `enableTerminalSandbox: false` (прямое выполнение в нативном окружении без ограничений);
  * `nonWorkspaceFileAccessPolicy: 1` (ALLOW).

### 3. Индикатор привилегий Root и быстрый доступ к настройкам в UI
* **Оптимизированное позиционирование `# ROOT`:** Индикатор перемещен в центр шапки интерфейса (`left: 50%`), полностью освободив правый угол с нативными кнопками (шестеренка Settings, перезагрузка, меню профиля).
* **Кнопка быстрых настроек `⚙`:** В плашку индикатора и в модальное окно диагностики добавлен прямой вызов настроек приложения, доступный в том числе из активного диалога.
* **Рабочее пространство по умолчанию:** Автоматическое создание и выбор рабочей директории `/storage/emulated/0/Projects/`.

## Ранее реализованные ключевые возможности (v2.4.1)

### 1. Поддержка встроенного веб-терминала и спавнера PTY (PR #19)
* **Низкоуровневый бинарный патч PTY-шеллы:** Устранено аварийное завершение терминала из-за отсутствия `/bin/bash` на Android. Реализован модульный бинарный патч с сохранением длины строки (`/bin/bash` ➔ `/bin///sh`, ровно 9 байт), безопасно перенаправляющий запросы спавнера ядра в системный шелл Android без сдвига смещений ELF-секций.
* **Приоритетная иерархия `$SHELL` в супервизоре процесса (`CoreEnvironment`):** Вместо жестко заданного `runtime/bin/bash` выстроена отказоустойчивая цепочка разрешения шелла:
  1. `$PREFIX/bin/bash` (полноценный bash окружения пользователя со всей поддержкой `.bashrc`, автодополнения и истории);
  2. `runtime/bin/bash` (встроенный bridge-рантайм);
  3. `/system/bin/sh` (гарантированный системный шелл Android).
* **Эмуляция терминала и база `terminfo`:** В окружение процесса добавлен экспорт `TERM=xterm-256color` и автоматическое подключение каталога `TERMINFO` из `$PREFIX/share/terminfo`, что предотвращает артефакты и искажения цветов и управляющих последовательностей ANSI в интерактивных консольных программах (`nano`, `htop`, mc).

### 2. Повышение стабильности локальной сборки пакетов (AAPT)
* В этапы сборки ресурсов `modules/builder/02_r_java.sh` и `modules/builder/06_package.sh` добавлен экспорт `export ANDROID_DATA="${ANDROID_DATA:-/data}"`. Это устраняет сбои компилятора `aapt` с кодом `SIGABRT (134)` при сборке APK непосредственно внутри ARM64 Android userspace.

## Ранее реализованные ключевые возможности (v2.4.0)

### 1. Безопасность и изоляция данных (Issue #6)
* Из релизных сборок полностью удален атрибут `android:debuggable="true"`.
* Устранена уязвимость, позволявшая локальному пользователю или стороннему приложению через `run-as com.agy` считывать OAuth-токены сессий и внутренние файлы конфигурации.
* Флаг отладки изолирован исключительно в dev-сборке (`com.agy.dev`).

### 2. Системный диалог выбора файлов (Issue #8)
* Устаревший ограниченный интерфейс Storage Access Framework (SAF) заменен на нативный системный Intent-селектор Android.
* Обеспечен прямой доступ к файлам, изображениям, видео и архивам из Галереи, Google Фото и любых сторонних файловых менеджеров.
* Реализовано автоматическое сохранение постоянных разрешений на чтение (`Intent.FLAG_GRANT_PERSISTABLE_URI_PERMISSION`).

### 3. Совместимость с процессорами архитектуры ARMv8.0-A
* Добавлена библиотека динамической эмуляции атомарных инструкций `liblse_compat.so` и низкоуровневый перехватчик `sigill_handler`.
* Устранены аварийные завершения с кодом `SIGILL: illegal instruction` на устройствах с чипсетами Qualcomm Snapdragon 680/685 (Cortex-A53 / Redmi Note 12).

### 4. Оптимизация авторизации OAuth
* Полностью устранен дисковый опрос (polling с интервалом 80 мс) и создание промежуточных файлов при входе в учетную запись.
* Захват URL авторизации переведен на прямой перехват стандартного потока вывода ядра (stdout) с мгновенной отправкой Intent в системный браузер.

### 5. Аппаратный интерфейс фонарика
* Добавлена консольная утилита управления вспышкой камеры: `torch on` / `torch off`.

### 6. Фоновый планировщик задач (`agy-daemon`)
* Реализован системный микро-демон (<10 МБ RAM, 0% CPU в режиме ожидания) для выполнения отложенных и периодических задач по расписанию (cron, интервалы).
* Добавлена поддержка отслеживания изменений файлов и отправка нативных уведомлений в панель Android через `agy-notify`.

### 7. Диагностика запуска ядра
* В интерфейс ошибки инициализации сервера добавлены действия «Copy Logs» и «Save Logs» для быстрого экспорта журнала сбоя в буфер обмена или файл.

### 8. Модульная структура конвейера сборки
* Исходный код разнесен по изолированным модулям: `modules/patches`, `modules/runner`, `modules/builder`.
* Внедрена аргументная передача параметров компиляторам `@java_sources.txt` и `@class_files.txt`, исключающая ошибку переполнения буфера командной строки ядра Linux (`ARG_MAX` / `E2BIG`).
